## Instructions

This entry adds **pwa**: an installable Progressive Web App surface — web app
manifest, a minimal Inertia-safe service worker with an offline fallback page,
the layout tags browsers look for, and client-side registration — driven by one
config file. It uses Rails 8.1's built-in `Rails::PwaController`; no gem is
added.

This is an explicit new-module adoption. The changelog filter skips the entry
until `pwa` is present in the downstream manifest, so apply these instructions
only after the maintainer chooses the module. Requires the `frontend` module
(layout + Vite entrypoint).

1. Create `config/initializers/pwa.rb` from the template and set the app's
   identity:

   ```ruby
   Rails.application.config.x.pwa.name = "Your App"
   Rails.application.config.x.pwa.short_name = "App"
   Rails.application.config.x.pwa.description = "One line about the app."
   Rails.application.config.x.pwa.theme_color = "#1f2937"
   Rails.application.config.x.pwa.background_color = "#ffffff"
   ```

2. Copy `app/views/pwa/manifest.json.erb` and `app/views/pwa/service-worker.js`
   from the template, overwriting the Rails-generated comment-only versions.
   Copy `public/offline.html`. Provide a 512×512 `public/icon.png` (the
   manifest reuses it for `any` and `maskable`; pad maskable artwork to the
   central ~80%).
3. In `config/routes.rb`, replace the commented PWA routes with:

   ```ruby
   get "manifest" => "rails/pwa#manifest", as: :pwa_manifest, format: true, constraints: { format: "json" }
   get "service-worker" => "rails/pwa#service_worker", as: :pwa_service_worker,
     defaults: { format: :js }, constraints: { format: "js" }
   ```

   The format pins are required: Rails collapses browser-like `Accept` headers
   to html, so without `defaults: { format: :js }` the extension-less
   `/service-worker` raises `MissingTemplate`; the `constraints` make mismatched
   URLs (`/manifest`, `/service-worker.json`) 404 at routing instead of 500.
4. In `app/views/layouts/application.html.erb`, read
   `pwa = Rails.application.config.x.pwa` at the top of `<head>`, use `pwa.name`
   for the `<title>` fallback and the `application-name` meta, add
   `<meta name="theme-color" content="<%= pwa.theme_color %>">`, and replace the
   commented manifest link with
   `<%= tag.link rel: "manifest", href: pwa_manifest_path(format: :json) %>`.
5. Copy `app/frontend/lib/pwa.ts` and `app/frontend/lib/pwa.test.ts`. In the
   page-wide Vite entrypoint (`app/frontend/entrypoints/application.ts`), import
   `registerServiceWorker` from `~/lib/pwa` and call it after `window` `load`
   (immediately if `document.readyState === "complete"`). The entrypoint is
   browser-only; the helper itself no-ops where `navigator.serviceWorker` is
   absent.
6. Copy `test/controllers/pwa_test.rb` and `docs/modules/pwa.md` into the app.
7. Run the verification below. Only after it succeeds, add `pwa: "0.5.0"` to
   `.template-manifest.yml` and set `template_version` to at least `"0.5.0"`,
   never lowering a newer value.

Read the module doc's **Gotchas** before deploying: the worker is sticky (bump
`CACHE_VERSION` when `offline.html` changes), precache uses `cache: "reload"`
because `public/` is served with a 1-year cache, a stopped dev server shows the
offline page, and Safari treats `*.localhost` as insecure.

## Verify

- `bin/rails test test/controllers/pwa_test.rb test/controllers/home_controller_test.rb`
  passes.
- `npm run check` is green (tsc ×2 + Vitest, including `pwa.test.ts`).
- `curl -s http://localhost:<port>/manifest.json | jq .name` prints the
  configured name; `curl -sI http://localhost:<port>/service-worker` reports
  `text/javascript`; `curl -sI http://localhost:<port>/manifest` reports 404.
- `bin/rails test` remains green.
- *(Human spot-check — optional for an unattended upgrade agent.)* Chromium
  DevTools → Application shows the manifest parsed without errors and a service
  worker activated at scope `/`; ticking **Offline** and reloading shows the
  offline page with its icon; online Inertia visits are unaffected.
