## Instructions

All four fixes come from the first real tenant deploy (licht-op-verlies-v6 →
Kamal → Hetzner). Apply each one; the Dockerfile ones are hard build failures,
the others are docs/ergonomics.

1. **Dockerfile — copy `.ruby-version` into the bundle stage.** The Gemfile
   reads `ruby file: ".ruby-version"`, so `bundle install` aborts without it.
   Change:

   ```dockerfile
   COPY Gemfile Gemfile.lock ./
   ```

   to:

   ```dockerfile
   COPY Gemfile Gemfile.lock .ruby-version ./
   ```

2. **Dockerfile — install Node in the build stage.** The stock slim Dockerfile
   has no JS toolchain, so `assets:precompile` → `vite:build_all` fails with
   `Errno::ENOENT: No such file or directory - npx`. In the `build` stage:

   - Add `node-gyp` and `python-is-python3` to the build-packages `apt-get install` line.
   - After that RUN, add:

     ```dockerfile
     # Install Node.js for the Vite production build (not shipped in the final image)
     ARG NODE_VERSION=22.14.0
     ENV PATH=/usr/local/node/bin:$PATH
     RUN curl -sL https://github.com/nodenv/node-build/archive/master.tar.gz | tar xz -C /tmp/ && \
         /tmp/node-build-master/bin/node-build "${NODE_VERSION}" /usr/local/node && \
         rm -rf /tmp/node-build-master
     ```

   - After the `bundle install` RUN, add:

     ```dockerfile
     # Install node modules (dev deps included — Vite itself is a devDependency)
     COPY package.json package-lock.json ./
     RUN npm ci
     ```

   - Append `&& rm -rf node_modules` to the `assets:precompile` RUN so the
     runtime image stays lean.

3. **config/deploy.yml — optional remote builder.** Replace the `builder:`
   block with:

   ```yaml
   # Optionally build on a remote docker host (e.g. the target box itself) to
   # avoid cross-arch emulation: KAMAL_BUILDER_REMOTE=ssh://user@host.
   builder:
     arch: <%= ENV.fetch("KAMAL_BUILDER_ARCH") %>
   <% unless ENV["KAMAL_BUILDER_REMOTE"].to_s.empty? %>
     remote: <%= ENV["KAMAL_BUILDER_REMOTE"] %>
   <% end %>
   ```

4. **DEPLOYING.md — two doc corrections.** (a) The `KAMAL_IMAGE` example must
   NOT include the registry host (`registry.server` is prepended; including it
   yields `ghcr.io/ghcr.io/...`): use `export KAMAL_IMAGE=me/my-app`. (b) After
   the "ensure `config/master.key` exists" step, document that a fresh clone
   cannot decrypt the template's `credentials.yml.enc` and must regenerate:
   `rm config/credentials.yml.enc && EDITOR=true bin/rails credentials:edit`,
   committing the new `.enc` and keeping the key untracked.

5. Verify: `docker build .` completes through `assets:precompile` (or, without
   docker, confirm the Dockerfile contains `.ruby-version` in the bundle-stage
   COPY and an `npm ci` before `assets:precompile`), and
   `KAMAL_BUILDER_REMOTE=ssh://u@h bin/kamal config` renders a `remote:` builder
   entry while unset leaves it absent.
