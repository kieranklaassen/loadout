## Instructions

Move Geneva Drive from 0.5.0 to 0.6.0. The release adds resumable steps,
per-step job options, a `report:` option on exception policies, and a partial
index that keeps the housekeeping in-progress recovery scan fast. It needs three
new migrations; until they run, `resumable_step` raises a configuration error and
everything else keeps working.

1. Back up any populated database before migrating.
2. In `Gemfile`, set `gem "geneva_drive", "~> 0.6.0"` and run
   `bundle update geneva_drive`. Confirm `bundle info geneva_drive` reports 0.6.0.
3. Run `bin/rails generate geneva_drive:install --skip`. `--skip` keeps the
   existing initializer and the existing (locally patched) nullable-hero
   migration untouched. It creates exactly these three files:
   - `db/migrate/*_add_metadata_to_geneva_drive_workflows.rb`
   - `db/migrate/*_add_started_at_index_to_geneva_drive_step_executions.rb`
   - `db/migrate/*_add_resumable_step_support_to_geneva_drive_step_executions.rb`

   If the generator gives two files the same timestamp or a seconds value of
   `60`, rename them to distinct, valid, ascending timestamps. If the generator
   offers to overwrite `AllowNullHeroOnGenevaDriveWorkflows`, decline.
4. In the started-at index migration, write the MySQL fallback array as
   `[ :state, :started_at ]` so rubocop-rails-omakase passes.
5. Run `bin/rails db:migrate`. `db/schema.rb` gains `metadata` (text) on
   `geneva_drive_workflows`, `cursor` (json) and `continues_from_id` (bigint) on
   `geneva_drive_step_executions`, an index on `continues_from_id`, and the
   partial index `index_geneva_drive_step_executions_in_progress_started_at`
   (`where: "state = 'in_progress'"`).
6. On SQLite production data, run `PRAGMA integrity_check` (expect `ok`) and
   `PRAGMA foreign_key_check` (expect no rows), and compare workflow and
   step-execution row counts to the pre-migration backup.
7. If the app copied `test/workflows/geneva_drive_smoke_test.rb`, change its
   version assertion to `assert_equal "0.6.0", GenevaDrive::VERSION`.
8. Update `docs/modules/geneva_drive.md` from the template (0.6.0, nine
   migrations, the recovery index now shipped, license links at `v0.6.0`).

## Verify

- `bin/rails test test/workflows/geneva_drive_smoke_test.rb test/migrations/geneva_drive_migration_test.rb test/jobs/recurring_schedule_test.rb`
  passes.
- `bin/rails runner 'p GenevaDrive::StepExecution.column_names.include?("cursor")'`
  prints `true`.
- `bin/rubocop` and `bin/rails test` are green.
