## Instructions

This entry registers **feature_flags** as a house module: [Flipper](https://www.flippercloud.io/docs)
for staged rollouts of big new features, in the shape Cora runs it (per-user
actors, a YAML flag registry that production always creates disabled, an
admin-only dashboard, a client reader, a rollout ladder, and a cleanup
migration). The module is **documentation-first**: no gem, migration, or
initializer ships in the template.

This is an explicit new-module adoption. The changelog filter skips the entry
until `feature_flags` is present in the downstream manifest, so apply these
instructions only after the maintainer chooses the module. Requires the `auth`
module (the actor is `Current.user`) and the `frontend` module (layout and Vite
entrypoint).

1. Copy `docs/modules/feature_flags.md` from the template into the app's
   `docs/modules/` (create the directory if absent).
2. Follow that doc's "Adopt into an existing app" steps: the three gems,
   `bin/rails g flipper:setup` and the migration, the initializer with the
   `:admins` / `:beta_testers` groups and the registry loader,
   `config.flipper.preload = false`, `config/flipper_flag_defaults.yml`, the
   admin-only `/admin/flipper` mount, the layout script tag plus
   `app/frontend/lib/flipper_flags.ts`, and the Vitest helper.
3. If the app already has Flipper, reconcile rather than replace: keep its
   flags, make sure every one has a registry entry, and adopt the pieces it is
   missing (most often the production-disabled default, the 404 gate, and the
   cleanup migration convention).
4. Run the verification below. Only after it succeeds, add
   `feature_flags: "0.6.0"` to `.template-manifest.yml` and set
   `template_version` to at least `"0.6.0"`, never lowering a newer value.

For an app that does not want feature flags: no action. This entry only affects
apps that list `feature_flags` in their manifest.

## Verify

- `docs/modules/feature_flags.md` exists in the app.
- If adopted: `bundle list | grep flipper` shows `flipper`, `flipper-active_record`,
  and `flipper-ui`; `bin/rails db:migrate:status` shows the flipper tables
  migration `up`; `bin/rails runner 'puts Flipper.features.map(&:name)'` lists
  every flag in `config/flipper_flag_defaults.yml`.
- If adopted: signed out or as a non-admin, `GET /admin/flipper` is 404.
- `bin/rails test` and `npm run check` are green.
