## Instructions

Move `ruby_llm` from 1.16 to the 2.x line. 2.0.0 stable also fixes
CVE-2026-67991 (GHSA-42r3-x6vx-x49x), so the bundler-audit ignore for it goes
away. Apps that already moved to 2.x by hand (happyhappy did, for
`ruby_llm-typesafe`) apply only the steps that are not done yet.

1. In `Gemfile`, set `gem "ruby_llm", "~> 2.0"` and run
   `bundle update ruby_llm`. `ruby_llm-schema` drops out of the lockfile and
   `schematist` comes in. Confirm `bundle info ruby_llm` reports 2.0.0 or newer
   2.x.
2. In `config/initializers/ruby_llm.rb`, delete these lines if present (2.0
   removed both settings; setting them only logs a warning):

   ```ruby
   # Persist chats/messages through the app's own Model registry with the current
   # acts_as API (opt in per-model with `acts_as_chat` etc.).
   config.model_registry_class = "Model"
   config.use_new_acts_as = true
   ```

   In Rails the model registry now reads a `ruby_llm_models` table when one exists
   and otherwise falls back to the bundled JSON catalog. If the app relied on a
   custom registry model, read the ruby_llm 2.0 upgrade notes before deleting it.
3. Leave the `ActiveSupport::Notifications.subscribe("chat.ruby_llm")` block as
   is. 2.x emits instrumentation through `config.instrumenter`, which its Railtie
   sets to `ActiveSupport::Notifications`.
4. In `config/bundler-audit.yml`, remove the `CVE-2026-67991` ignore and its
   comment. If that leaves no entries, write `ignore: []`.
5. Replace the app's `docs/modules/ruby_llm.md` with the template's copy (or
   update its version, initializer bullet, and adopt step to `~> 2.0`).

## Verify

- `bin/rails test test/initializers/ruby_llm_test.rb` passes.
- `bin/rails runner 'puts RubyLLM::VERSION'` prints 2.x and boot logs no
  `model_registry_class` / `use_new_acts_as` warning.
- `bin/bundler-audit` reports no vulnerabilities.
