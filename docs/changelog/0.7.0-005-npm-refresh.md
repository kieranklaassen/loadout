## Instructions

Bring the JavaScript toolchain current, including two majors: TypeScript 7 and
Vitest 5. Vitest 5 also clears GHSA-82fw-gwwq-j7x9 (`@vitest/mocker` path
traversal) that `npm audit` reports against Vitest 4.1.10 and older.

1. Use Node 24 (see entry 0.7.0-001) and its bundled npm 11. Do not regenerate
   the lockfile with npm 12; CI's `npm ci` runs on the npm that ships with Node 24.
2. Update every dependency to its latest release:

   ```bash
   npm install -D @inertiajs/core@latest @testing-library/react@latest \
     @testing-library/user-event@latest @testing-library/jest-dom@latest \
     @types/react@latest @types/react-dom@latest jsdom@latest \
     typescript@latest vite@latest vite-plugin-ruby@latest vitest@latest
   npm install @inertiajs/react@latest @inertiajs/vite@latest \
     @tailwindcss/forms@latest @tailwindcss/typography@latest \
     @tailwindcss/vite@latest @vitejs/plugin-react@latest \
     react@latest react-dom@latest tailwindcss@latest
   ```

   Add any app-specific packages to the matching command. Template versions after
   the update: react / react-dom 19.3.0, @inertiajs/* 3.7.1, vite 8.3.1,
   @vitejs/plugin-react 6.1.1, vite-plugin-ruby 5.2.4, typescript 7.0.2,
   vitest 5.0.1, jsdom 30.1.1, @types/react 19.3.0.
3. Check that the top-level `"name"` in `package-lock.json` is still the app's
   name; npm rewrites it from the directory name when the lockfile is regenerated
   in a differently named checkout.
4. The template's `tsconfig.app.json` / `tsconfig.node.json` and
   `vitest.config.ts` needed no changes. If `tsc` rejects a compiler option in the
   app's own tsconfig as removed or deprecated, replace it with the option the
   error message names (typically `"moduleResolution": "bundler"` and explicit
   `paths`), then rerun the type check.
5. Run `npm outdated` (expect no output) and `npm audit` (expect
   `found 0 vulnerabilities`).
