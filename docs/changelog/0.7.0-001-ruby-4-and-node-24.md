## Instructions

Move the app to the current stable runtimes: Ruby 4.0.7 and Node 24.21.0 (the
Node 24 Active LTS line). CI reads both from the version files, and the
Dockerfile pins them explicitly, so all three must agree.

1. Set `.ruby-version` to `4.0.7`. If the `Gemfile` uses `ruby file: ".ruby-version"`
   nothing else changes there; if it hard-codes a version, replace it with
   `ruby file: ".ruby-version"`.
2. Set `.node-version` to `24` (CI's `actions/setup-node` resolves the newest
   24.x). If the app uses `.nvmrc` instead, set it to `24` as well.
3. In `Dockerfile`, set:

   ```dockerfile
   ARG RUBY_VERSION=4.0.7
   ...
   ARG NODE_VERSION=24.21.0
   ```

   `ruby:4.0.7-slim` is Debian trixie. The template's package lists
   (`curl libjemalloc2 libvips sqlite3` at runtime, `build-essential git libvips
   libyaml-dev node-gyp pkg-config python-is-python3` at build) resolve unchanged
   there. If the app installs extra Debian packages, confirm each one still exists
   in trixie.
4. Install Ruby 4.0.7 locally, then run `bundle install`. Bundler rewrites the
   `RUBY VERSION` section of `Gemfile.lock` to `ruby 4.0.7`. Also run
   `bundle update --bundler` so `BUNDLED WITH` is the current stable Bundler
   (4.0.21 at the time of writing; never a `.beta`).
5. Ruby 4.0 moved more standard-library code out of the default gems. Boot the
   app and run the suite; if Ruby warns that a library "is not part of the default
   gems" or a `require` raises `LoadError` (common ones: `ostruct`, `pstore`,
   `benchmark`, `cgi` beyond `cgi/escape`), add that gem to the `Gemfile` rather
   than silencing the warning. The template itself needed no additions.
6. Update any docs that name the old versions (the template's `README.md` stack
   line and `docs/modules/deploy.md` say `Ruby 4.0.7` and `ruby:4.0.7-slim`).

## Verify

- `ruby -v` reports 4.0.7 and `node -v` reports v24.x inside the app directory.
- `bin/rails test test/deploy_config_test.rb` passes.
- `bin/rails test` and `npm run check` are green.
- If Docker is available, `docker build .` completes and
  `docker run --rm <image> ruby -v` reports 4.0.7.
