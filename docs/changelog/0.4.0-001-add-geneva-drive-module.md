## Instructions

This entry adds [Geneva Drive](https://github.com/julik/geneva_drive) 0.5.0 as
a durable workflow engine backed by Active Record and Active Job.

This is an explicit new-module adoption. The normal changelog filter skips the
entry until `geneva_drive` is present in the downstream manifest, so apply these
instructions only after the maintainer chooses the module. Do not install it
solely because the app already has `jobs`.

1. Verify the `jobs` module is already adopted: Solid Queue is the Active Job
   adapter, it uses a separate queue database, a worker consumes the `default`
   queue (or `*`), and `config/recurring.yml` is active. Stop and adopt `jobs`
   first if any prerequisite is missing.
2. Add the released dependency to `Gemfile`:

   ```ruby
   gem "geneva_drive", "~> 0.5.0"
   ```

   Run `bundle install` and verify `bundle info geneva_drive` reports 0.5.0.
3. Run `bin/rails generate geneva_drive:install`. Keep the generated initializer
   and all six v0.5.0 migrations. If the initializer comment names
   `stuck_executing_threshold`, correct it to the actual setting
   `stuck_in_progress_threshold`.
4. Review the generated migrations and back up any populated database. In
   `AllowNullHeroOnGenevaDriveWorkflows`, remove the inbound
   `geneva_drive_step_executions.workflow_id` foreign key before the generated
   SQLite parent-table swap and restore it afterward with `on_delete: :cascade`;
   otherwise the drop deletes existing step history. Run `bin/rails db:migrate`;
   confirm `db/schema.rb` contains
   `geneva_drive_workflows`, `geneva_drive_step_executions`, and the partial
   unique indexes `index_geneva_drive_workflows_unique_ongoing` and
   `index_geneva_drive_step_executions_one_active`.
5. Merge this task into the shared anchor in `config/recurring.yml`, so
   production, development, and test inherit it:

   ```yaml
   geneva_drive_housekeeping:
     class: "GenevaDrive::HousekeepingJob"
     schedule: "*/30 * * * *"
   ```

6. Give the test environment a separate Solid Queue database matching
   production, while leaving Active Job on its test adapter by default:

   ```yaml
   test:
     primary:
       <<: *default
       database: storage/test.sqlite3
     queue:
       <<: *default
       database: storage/test_queue.sqlite3
       migrations_paths: db/queue_migrate
   ```

   Add this to `config/environments/test.rb`:

   ```ruby
   config.solid_queue.connects_to = { database: { writing: :queue } }
   ```

7. Copy `docs/modules/geneva_drive.md`,
   `test/workflows/geneva_drive_smoke_test.rb`,
   `test/migrations/geneva_drive_migration_test.rb`, and the Geneva Drive
   assertions from `test/jobs/recurring_schedule_test.rb` into the app. Adapt
   the smoke workflow's hero fixture to an existing domain model.
8. Read the module doc before defining production workflows. External side
   effects require stable domain idempotency keys; exception messages and full
   backtraces are persisted; the open-source engine has no admin UI. Confirm
   whether LGPLv3 or a separately purchased commercial license is the correct
   basis for the downstream app.
9. Run the verification below. Only after it succeeds, add
   `geneva_drive: "0.4.0"` to `.template-manifest.yml`. Set `template_version`
   to at least `"0.4.0"`, but never lower a newer value.

For every future Geneva Drive version change, including a patch update, read the
upstream changelog, rerun `bin/rails generate geneva_drive:install`, review and
back up before new migrations, migrate, rerun verification, and only then bump
the module manifest version.

## Verify

- `bundle info geneva_drive` reports 0.5.0.
- `RAILS_ENV=test bin/rails db:prepare` succeeds for both primary and queue.
- `bin/rails test test/workflows/geneva_drive_smoke_test.rb test/jobs/recurring_schedule_test.rb`
  passes.
- `bin/rails test test/migrations/geneva_drive_migration_test.rb` proves a
  populated SQLite workflow keeps its step history and valid foreign keys.
- `bin/rails runner 'puts [GenevaDrive::Workflow.table_exists?, GenevaDrive::StepExecution.table_exists?].inspect'`
  prints `[true, true]`.
- `bin/rails test` remains green.
