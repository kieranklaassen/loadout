# Inertia + React setup

Survey of 12 Kieran Klaassen Rails projects for the "Inertia + React setup" pattern area.

## Summary

Eight of the twelve projects use `inertia_rails` + `@inertiajs/react`; four do not (`leva`, `blazer-ai` are Rails engine gems with no frontend at all; `erf-rails` is plain Hotwire/Turbo/Stimulus; `every` is a pre-Inertia Rails app using jsbundling-rails with jQuery-style JS components). Among the eight Inertia apps there is a clear generational split. The two oldest/Jumpstart-derived apps (**cora**, **lifegarden**) predate the current toolchain: `app/javascript`, esbuild via `jsbundling-rails`, and (in cora's case) Inertia layered on top of an otherwise Hotwire/Turbo app for specific SPA-like surfaces only. The six newer apps (**atelier, tada, diskman, thinkroom, riffrec-dashboard, kieranklaassen-com**) converge on one modern stack: `app/frontend` + `vite_rails`/`vite-plugin-ruby`, Inertia's built-in `pages: '../pages'` auto-resolver, snake_case page paths that mirror `controller#action` (e.g. `render inertia: "children/index"` → `app/frontend/pages/children/index.tsx`), `config.use_script_element_for_initial_page = true`, `config.encrypt_history = true`, `config.always_include_errors_hash = true`, and a dedicated `InertiaController < ApplicationController` base class carrying `inertia_share`. Two apps (**thinkroom**, **kieranklaassen-com**) run real SSR (`ssr_bundle` + `ssr_url` pointed at a Node process, with a hand-rolled `Net::HTTP` open/read timeout patch on `InertiaRails::SSRRenderer`); the rest are CSR-only. Only **cora** uses Alba + Typelizer (`app/resources/*_resource.rb`) to serialize props with generated TS types — every other project hand-writes prop hashes and TS types.

### thinkroom
- Gem: `gem "inertia_rails", "~> 3.21"`. JS: `@inertiajs/react ^3.5.0`, `@inertiajs/vite ^3.5.0`, `vite ^8.1.0`, `vite-plugin-ruby ^5.2.2`, `tailwindcss ^4.3.1`. Uses house `"riffrec"` package for feedback capture (same as tada).

- `config/initializers/inertia_rails.rb`: `config.version` wrapped in a `Mutex`-guarded `InertiaController.safe_vite_digest` (works around a `ViteRuby.digest` `chdir` race under concurrent requests — documented as a real production bug fix). `config.encrypt_history = true`, `config.always_include_errors_hash = true`, `config.use_script_element_for_initial_page = true`, `config.use_data_inertia_head_attribute = true`.

- Base `InertiaController < ApplicationController`: includes `RubyNative::InertiaSupport`; `inertia_share viewer: -> { ... }` builds an account/guest-identity shape, reading a client-written `pruf_guest` cookie so SSR can render the correct guest display name at first paint with no post-hydration flash.
- Entrypoint `app/frontend/entrypoints/inertia.tsx`: `pages: "../pages"` shorthand (not manual glob) plus a custom `setup({ el, App, props })` that branches on `el` (SSR: return the JSX tree for `renderToString`) and on `el.dataset.serverRendered === "true"` (client: `hydrateRoot` vs `createRoot`). Wrapped in `<RiffrecProvider forceEnable>`. Root layout `application.html.erb` renders `<title data-inertia>`, open-graph meta driven by `@open_graph`, and `data-native-app` attribute for the Ruby Native shell.
- No `config/deploy.yml` role dedicated to an SSR process was found — the Node SSR server is started by `bin/docker-entrypoint` inside the same container/image (per the initializer's comments), not a separate Kamal role.

## Recommendation for compound-stack-rails

1. **Adopt the six-project modern stack wholesale**: `inertia_rails` + `@inertiajs/react` + `vite_rails`/`vite-plugin-ruby` + `app/frontend` (not `app/javascript`). This is what atelier, tada, diskman, thinkroom, riffrec-dashboard, and kieranklaassen-com all converged on independently — cora and lifegarden's `app/javascript` + esbuild setup is legacy Jumpstart baggage, not a pattern to propagate.
2. **Page convention**: snake_case directories that mirror `controller#action` (`app/frontend/pages/<resource>/<action>.tsx`), matched to `render inertia: "<resource>/<action>", props: { ... }` in controllers. This is the majority pattern (tada, thinkroom, riffrec-dashboard, kieranklaassen-com) and reads directly off Rails' own routing conventions — prefer it over cora/diskman's PascalCase `Resource/Action.tsx` style.
3. **Entrypoint**: use the `createInertiaApp({ pages: '../pages', ... })` shorthand (diskman, thinkroom, riffrec-dashboard, kieranklaassen-com all use it) instead of hand-rolled `import.meta.glob` resolvers (atelier, tada) — less boilerplate, same result. Support both CSR and SSR from day one with the `hydrateRoot`/`createRoot` branch on `el.dataset.serverRendered === "true"` (thinkroom, kieranklaassen-com), even if SSR starts disabled — it costs nothing and means SSR can be turned on later without touching the entrypoint.
4. **Base `InertiaController < ApplicationController`**: adopt this from tada/thinkroom/riffrec-dashboard as the standard for every generated app — controllers inherit from it, not `ApplicationController` directly, and `inertia_share` calls (viewer/current_user, flash, locale) live there so a new page cannot ship ungated by omission (riffrec-dashboard's explicit rationale for putting the auth include on the base class).
5. **`config/initializers/inertia_rails.rb` defaults**: standardize on `config.version = -> { ViteRuby.digest }`, `config.encrypt_history = true`, `config.always_include_errors_hash = true`, `config.use_script_element_for_initial_page = true`, `config.use_data_inertia_head_attribute = true` — this exact combination appears in 5 of 6 modern apps (diskman lacks `encrypt_history` toggle nuance but matches otherwise).
6. **SSR**: make it available but off-by-default, following thinkroom/kieranklaassen-com's shape — `ssr_bundle`/`ssr_url` config, `on_ssr_error` logging with CSR fallback, and **carry over the `Net::HTTP` open/read timeout monkeypatch** (`config/initializers/inertia_ssr_timeout.rb`) verbatim; it fixes a real gap in `inertia_rails` (no configurable SSR HTTP timeout) that both SSR-enabled apps independently patched the same way. This patch is a strong candidate to eventually push upstream to `inertia_rails` or extract into a shared house gem rather than re-copy per app.
7. **Do not default to Alba/Typelizer.** Only cora uses it, and cora is otherwise the least representative project (Hotwire-primary with Inertia bolted onto specific surfaces, esbuild not Vite). Ship it as an optional/documented add-on for apps that want typed serializers, not as the starter's default prop-passing mechanism — the majority pattern across the fleet is plain hashes built in controllers (`props: { posts: ... }`, `.slice(:id, :name, :email)`, `.as_props` methods on models).
8. **Skip Alba/Typelizer's absence is itself notable**: six of eight Inertia apps hand-write props and, where present, hand-write matching TS types (`types/globals.d.ts`, `types/page.ts` in riffrec-dashboard/kieranklaassen-com). If type-safety is a starter-template goal, typelizer is worth reconsidering later, but it should not block v1 given how rarely it's actually used.
9. **House packages worth bundling as optional starter modules**: `RubyNative::InertiaSupport` (native-app prop sharing, used in tada/thinkroom) and the `riffrec` npm package (feedback capture, used in tada/thinkroom/riffrec-dashboard) are recurring but not universal — treat as opt-in modules, not defaults.
